# 连续控车对话

规则完整匹配、模型补充理解及异步边界见 [意图接入说明](intent-integration.md)。

## 可实测序列

1. “副驾车窗开一半” → “再开一点” → “关上吧”。
2. 页面刷新后直接说“再开一点” → 暂存 +10 个百分点动作 → 回答“右车窗” → 继续追问前后 → 回答“右后窗”或“后面” → 按补答时右后窗 current + 0.1 执行。
3. “开一半” → 回答“右后窗” → 右后窗半开。
4. 追问后等待 60 秒，或点击控制卡片/三维车窗、拖动滑块、点击按钮 → 暂存动作清空；仅回答位置不执行。
5. 说“取消”或点击页面取消按钮 → 待执行动作和续接上下文同时清空 → 仅回答位置不能恢复旧动作，需要重新说明动作。
6. 录音期间手动切换车窗 → 该次录音所有后续最终结果失效；停止后重新录音可继续。

左右均按车辆自身方向。“右车窗”“左车窗”没有明确前后，不能自动选前窗，也不会自动操作两窗：保留待执行动作并追问前后。已限定右侧后，可以回答“右后窗”或“后面”；左侧同理。部分位置补答只缩小候选目标，不刷新原始60秒截止时间；候选位置冲突时继续追问，不执行。

“副驾／主驾”是明确位置，仍分别表示右前／左前。“右侧两个车窗”明确表示多窗，绝对开度可执行，但不会建立单窗续接上下文。

## 存储与执行

上下文、待澄清动作和交互版本在 `src/stores/vehicle.ts`：

- `dialogueContext`：单窗 target、expiresAt。
- `pendingAction`：尚未确定目标的 absolute/relative 动作、原句、expiresAt、候选目标 candidates；没有预先保存开度。
- `interactionVersion`：手动行为/文字提交递增的版本。
- `submitText`：语音与文字的语义入口；解析、版本校验、过期检查、追问与补答。
- `dispatch`：唯一车辆执行入口；相对动作在此同步读取 current 并加减 0.1，然后限制在 [0,1]。current 不重置，运动中可以反向。

解析器 `src/commands/vehicle-command.ts` 是纯函数，返回 absolute、relative 或仅目标的回答。上下文不会使用界面 selected 或 lastCommand 推断。

有效单窗对话指令被接受后建立/刷新 60 秒续接上下文。追问时清空单窗上下文并创建 60 秒待执行动作；无效回答不刷新期限。补答成功后消耗待执行动作并建立单窗上下文。新动作取代旧待澄清动作，避免一个回答执行两个动作。

上下文和待执行动作到期、手动选择（即使选择同一窗）、按钮、滑块、开始/停止循环播放时一起清空。手动操作必须走 action，页面卡片与三维拾取均调用 `selectWindow()`。视角旋转/缩放不清空。多窗对话成功后清空单窗上下文。目标冲突或无法解析的明确位置不回退到旧目标。

“取消”“取消待执行动作”“请取消吧”等解析为独立取消意图。取消立即清空 pendingAction 和 dialogueContext，返回已取消反馈，不生成车辆运动指令；已经发出的车窗运动继续执行原目标。取消后的位置回答不能恢复旧动作，重复取消结果不重复处理。“不要取消”等否定表达仍拒绝。页面提供同义的取消按钮。

停止/重新开始录音不清空对话目标，允许跨录音回答追问。页面刷新不持久化。动画 tick 清理过期状态，同时每次 submitText 也检查绝对过期时间，所以后台标签页计时暂停不会让过期补答生效。

文字输入与语音共享上下文；文字提交还会使此前正在进行的录音失效，防止旧语音结果套用新文字目标。

## 语句开始事件与延迟结果

**交互版本固定点是录音开始，不是 ASR 结果到达。**

1. 用户点击开始，`createMicrophone.start()` 同步触发 `connecting`，在请求权限/后端/网络之前由 `VoiceTurns.begin(store.interactionVersion)` 固定版本。
2. 收到 ready 后绑定 session，不重读当前版本。
3. 后端每个 index 第一次出现时发送 `sentence_start`，之后才转发 interim/final。slice_type=0、1、2 都能触发此合成事件；同 index 只发送一次。携带云端 start_time 供排查，不用云端时间或到达时间推算手动版本。
4. `VoiceTurns.observe()` 将句子绑定到录音开始时固定的版本。直接 final、没有 sentence_start、第一条结果是 interim，都有同样的 begin 版本兜底。
5. 只有 final 进入 submitText；版本不同就返回失效提示，不执行、不建立上下文、不暂存动作，也不清除较新的有效上下文。

因此即使“手动操作 → 首条 sentence_start/interim/final 才到达”，该结果也不会借用手动之后的版本获得执行资格。代价是同一次录音内，手动操作之后的新句子也被拒绝（含明确目标指令），需要重新开始录音；首版不尝试根据云端时间推断真实录音边界。

`FinalResults` 仍按 session:index 去重。`VoiceTurns` 额外拒绝低于已处理最终 index 的乱序 final，避免旧句子在新句子之后覆盖目标。store 对语义输入 id 也做去重，包括追问和失效结果；重复结果不会执行动作或刷新任何截止时间。

## 页面反馈

显示当前续接目标、待澄清动作，以及识别/输入文本、执行目标和结果。相对动作反馈记录执行瞬间的 current 与计算后的目标开度。上下文失效后显示“无，请先明确目标”。超时后的目标回答会提示“没有待执行的动作”。

## 验证与启动

已通过构建、命令与上下文测试、原有 V8 状态/运动测试、模拟 ASR 网关测试。网关测试覆盖首条 slice_type=1、首条直接 slice_type=2，以及重复 slice_type=0 的 sentence_start 顺序与去重。最新测试补充左右含糊目标追问、部分位置补答、追问不延长有效期、语音/文字取消、取消后位置回答不执行旧动作。新增真实连续对话需要用户重启后实测；用户已确认此前腾讯云配置和原语音流程通过实测。

```sh
npm run build
npm run test:commands
node scripts/test-asr.mjs
node scripts/check-v8.mjs
```

启动时重启后端以加载新增 sentence_start 事件；前端刷新或重新启动。凭据保留在原来的 server/.env.local，本次没有读取或覆盖。

```sh
npm run dev:server
# 另一个终端
npm run dev
```
