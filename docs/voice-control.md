# 语音与文字控车

热词配置、模型兜底及顺序/失效处理已实现，接入方式见 [模型意图理解接入](intent-integration.md)。

连续对话、60秒上下文与追问补答已实现，最新规则见 [连续对话说明](continuous-dialogue.md)。

当前可用：按钮、滑块、文字以及 ASR 最终识别句子共用 `useVehicleStore().dispatch(command)`。前端不保存腾讯云凭据，浏览器只连接同源 `/api/asr`，后端负责腾讯云签名及转发。

## 启动

在 `server/.env.local` 填入腾讯云控制台提供的 `TENCENT_APP_ID`、`TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`。模板为 `server/.env.example`，本地配置已被 Git 忽略。不要将密钥填入根目录的 `VITE_` 变量。默认引擎为 `16k_zh`；腾讯云账号需已开通实时语音识别并有可用额度。

分别打开两个终端，在项目根目录执行：

```sh
npm run dev:server
```

```sh
npm run dev
```

访问 http://127.0.0.1:5173/ 。后端监听 127.0.0.1:8787，Vite 转发 HTTP 与 WebSocket。更改后端密钥后需重启后端。`/api/health` 仅返回健康和是否已配置，不返回密钥。

先通过文字输入验证目标位置，再点击“开始语音控车”。首次使用需允许麦克风；说完可再次点击停止，客户端会等待最终结果。每次录音最长60秒，支持同一会话多条完整句子。界面展示中间转写，但只对句子最终结果执行。没有听清、位置不明、动作冲突或幅度不明确时提示重说，不猜测目标。

用户已确认腾讯云后端配置和原语音链路通过实测。本次新增连续对话通过本地自动化测试，待重启后重新实测；自动化网关测试使用本机模拟上游。

## 表达范围

按左舵车、车辆自身左右方向解释，与镜头角度无关。

| 表达 | 结果 |
| --- | --- |
| 副驾后面的车窗开一半 | 右后窗，50% |
| 关闭所有车窗 | 四窗，0% |
| 主驾车窗打开 | 左前窗，100% |
| 右前车窗开到百分之三十 | 右前窗，30% |
| 左后窗开到25% | 左后窗，25% |
| 两个后窗全部打开 | 左后与右后，100% |
| 所有车窗半开 | 四窗，50% |

“打开车窗”可使用有效单窗上下文，无上下文则暂存动作并追问位置；“再降一点”表示当前开度增加10个百分点。“关闭一半”、否定句、问句、同句冲突动作等保守拒绝。首版是有限规则语法，并非任意自然语言理解。开度数值沿用当前规范化运动行程。

## 状态与去重

- 指令包含 id、source、targets、openness、text；按钮、滑块通过相同 dispatch 更新 target，渲染层仍读取同一 Pinia current/target。
- 当前开度持续推进，不被新目标重置，因此运动中关闭或打开可直接反向。
- 腾讯云 `slice_type=0/1` 仅显示文本；`slice_type=2` 才生成可执行最终句子。流结束的 `final=1` 只结束会话，不再次控车。
- 后端和前端都用会话加句子 index 去重，车辆入口另按 command id 去重。同文本在新句子或新会话可以再次执行。
- 新录音、取消、组件销毁会作废旧连接，阻止旧连接回调执行。识别错误会释放录音资源；停止录音后先发送尾部 PCM，再发送 end，等待最终句子与 done。
- 页面显示识别文本、解析目标以及运动中/完成/被后续操作替换。目标由最新有效指令确定；无效输入不会改动车辆。

## 文件

- `src/commands/vehicle-command.ts`：统一指令类型、文字解析。
- `src/stores/vehicle.ts`：唯一执行入口与运动状态。
- `src/components/VoiceControl.vue`：录音/文字入口、解析和反馈。
- `src/voice/final-results.ts`：最终句子幂等处理。
- `src/voice/microphone.ts`：录音连接生命周期。
- `public/pcm-worklet.js`：实际采样率至 16kHz 重采样、PCM16 单声道、200ms 分片。
- `server/asr.mjs`：腾讯云签名、WebSocket 转发、会话去重、录音时限及错误处理。

签名和接口依据 [腾讯云实时 ASR WebSocket 官方文档](https://cloud.tencent.com/document/product/1093/48982)。服务端不记录原始音频、完整签名 URL 或密钥。浏览器在停止、失败及销毁时停止麦克风轨道。

## 验证

```sh
npm run build
npm run test:commands
node scripts/test-audio.mjs
node scripts/test-asr.mjs
node scripts/check-v8.mjs
```

覆盖中文解析、歧义拒绝、最终句子与命令去重、反向运动、暂停与完成，16/44.1/48kHz 录音数据转换，后端签名、健康接口、缺密钥以及模拟上游的握手/二进制数据/end/中间结果/重复最终结果/done。

实际麦克风验收顺序：右后窗半开 → 关闭所有车窗 → 运动中反向 → 重复说同样指令 → 只说“打开车窗” → 静音结束 → 拒绝录音权限 → 断网/重试。

手机录音需要可信 HTTPS 与 WSS。同源代理和后端 `ALLOWED_ORIGINS` 需配好；当前后端只监听本机，正式对外部署还需加访问认证与服务端限流。当前构建沿用完整 V8 模型，存在原有包体积提醒。
